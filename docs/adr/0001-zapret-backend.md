# ADR 0001 — Оставаться на zapret v1, но убрать привязку к нему

- **Дата:** 2026-08-03
- **Статус:** принято
- **Версия Nova:** 1.31

## Контекст

Nova поставляет `bin/winws.exe` из проекта [bol-van/zapret](https://github.com/bol-van/zapret).
Установленная версия проверена локально:

```
> bin/winws.exe --version
github version v72.13 (87e058624c72863db53bdaf7fb6f16576dddb6ab)
```

Обновлено с v72.12 до v72.13 в этой же сессии. Набор опций **побайтово
идентичен** предыдущей версии — сверено через `diff` вывода `--help`, — поэтому
ни IR, ни корпус стратегий правок не потребовали. Полный справочник:
[`docs/reference/winws-v72.13-help.txt`](../reference/winws-v72.13-help.txt).

Появился [bol-van/zapret2](https://github.com/bol-van/zapret2) — новое поколение
того же автора, где Windows-бинарь называется `winws2.exe`. Вопрос: переходить ли
Nova на него.

## Что установлено фактами

**zapret2 реален и активен.** Создан 2025-11-17, релиз v1.0.4 от 2026-07-31.
Но **zapret v1 тоже активен**: v72.13 от 2026-07-21. Автор публикует оба бинаря
рядом в `zapret-win-bundle` и не выражает предпочтения.

**Командная строка несовместима.** Из двадцати опций, которыми пользуется Nova,
без изменений переживают переход ровно шесть: `--filter-tcp`, `--filter-udp`,
`--hostlist`, `--hostlist-exclude`, `--ipset`, `--new`. Остальные четырнадцать
удалены или перестроены. Ключевое: вся группа `--dpi-desync*` заменена на
`--lua-desync=<функция>`, потому что вся логика манипуляции трафиком вынесена из
C в Lua. `nfqws2` использует `getopt_long_only`, то есть неизвестные опции
отвергаются, а не игнорируются — тихой деградации не будет, будет отказ старта.

**Выигрыш в CPU реален.** `--wf-tcp-empty=0` стал значением по умолчанию, что по
документации автора даёт около 50% экономии CPU при интенсивной загрузке.
Фильтры WinDivert на уровне payload вместо захвата целого порта дают ещё больше.

**Но выигрыш условный.** По умолчанию zapret2 отдаёт в Lua *весь* трафик. Без
корректно выставленных `--payload`, `--out-range` и `--filter-l7` на каждом
профиле он **медленнее** v1, а не быстрее.

**Новые классы отказов.** winws2 требует при запуске `--lua-init=@lua/zapret-lib.lua`
и `--lua-init=@lua/zapret-antidpi.lua` — около 141 КБ скриптов, которые надо
поставлять и версионировать вместе с exe. Рассинхрон версий exe и Lua — отказ,
которого в v1 не существует. В `docs/changes_compat.txt` уже зафиксированы два
слома API (`NFQWS2_COMPAT_VER` v2 и v3), `LUA_COMPAT_VER` дошёл до 6.

**Зрелость не доказана.** В свежем changelog: исправление неверного разбора IPv6,
потерянная деинициализация WinDivert с полной потерей интернета при исчезновении
логической сети, use-after-free в таймерах.

**IPC нет ни там, ни там.** Управление только через Unix-сигналы, на Windows
недоступные. Смена стратегии в любом случае означает перезапуск процесса.

**Cloudflare-специфики в zapret2 нет.** Есть более гибкие примитивы
(`tls_mod sni=`, `padencap`, `tls_client_hello_clone`), но готового решения нет —
автор осознанно отказывается публиковать рецепты.

### Проверенная гипотеза, оказавшаяся ложной

Исследование утверждало, что Nova уже сегодня использует режимы `split`, `split2`
и `disorder`, которых нет в актуальном zapret v1, и что эти стратегии сломаны.
В корпусе они действительно есть — 19 профилей. **Проверка на реальном бинаре
это опровергла:**

```
mode=split2     exit=0
mode=split      exit=0
mode=disorder   exit=0
mode=bogusmode  exit=1  ::  invalid dpi-desync mode
```

Это недокументированные обратно-совместимые алиасы: их нет в `--help`, но они
принимаются. Сегодня это не баг. Но в zapret2 их нет вообще, поэтому IR
нормализует их в `multisplit`/`multidisorder` при разборе.

## Решение

**Не переходить на zapret2 сейчас. Оставить winws v1 значением по умолчанию.**

**Одновременно — убрать привязку корпуса стратегий к синтаксису v1.** Стратегии
описываются намерением («расщепить ClientHello по маркеру SNI, отправить
поддельный пакет с плохой контрольной суммой, TTL 4»), а конкретный бэкенд
рендерит это в свой синтаксис.

Абстракция строится именно сейчас, потому что это самый дешёвый момент — крейт
`nova-zapret` пишется с нуля, — и потому что именно она делает решение обратимым.

## Последствия

- Корпус стратегий хранится как IR, а не как argv. Добавление zapret2 — это новый
  `Emitter`, а не переписывание корпуса.
- Nova получает возможность отрендерить одну стратегию в оба синтаксиса и сравнить
  их на одной машине — без этого осмысленное сравнение невозможно.
- Опции, которых нет в IR, сохраняются в `Strategy::passthrough` дословно, поэтому
  round-trip под v1 не теряет ничего. Эмиттер v2, когда появится, обязан
  **отказаться** обрабатывать такую стратегию, а не молча ослабить её.
- Тест `unmodelled_options_stay_within_the_reviewed_set` фиксирует список из 37
  опций, которые корпус использует, а IR не моделирует. Появление новой опции
  ломает тест — это принудительное решение о её отображении в zapret2.

## Условия пересмотра

Вернуться к вопросу примерно через полгода, при выполнении **всех** условий:

1. `NFQWS2_COMPAT_VER` и `LUA_COMPAT_VER` не менялись.
2. В changelog нет новых критических багов разбора пакетов или работы с драйвером.
3. Есть измеренный на нашем железе выигрыш CPU на профиле с корректными
   `--payload` / `--out-range` / `--filter-l7`.

Отдельный триггер для досрочного пересмотра: если понадобится конструирование
payload с «белым» SNI для Cloudflare — Lua-реконструктор TLS в zapret2 здесь
объективно мощнее v1.

## Ловушки для будущего эмиттера v2

Зафиксированы, чтобы не переоткрывать:

1. `autottl` использует запятую вместо двоеточия: `delta,min-max`.
2. IPv6 больше не наследует значения от IPv4 — `ip6_ttl`/`ip6_autottl` надо
   выставлять всегда, иначе к IPv6 не применится ничего.
3. `tcp_ts` почти всегда требует парного `tcp_ts_up`.
4. `tls_mod` как аргумент экземпляра рерандомизируется на **каждом** пакете, тогда
   как v1 рандомизировал один раз при старте. Поведение v1 воспроизводится только
   через `--lua-init`.
5. `badseq` не имеет прямого аналога — нужно явно писать `tcp_seq` и `tcp_ack`.
6. `--wf-tcp-empty=0` ломает счётчик пакетов `n`; логика, завязанная на номера
   пакетов, должна перейти на счётчик данных `d`.

## Риск бездействия

Всё новое развитие техник (`oob`, `zapret-obfs`, таймеры, оркестраторы) идёт
только в zapret2. v1 будет постепенно терять эффективность по мере эволюции DPI.
Именно поэтому абстракция строится сейчас, а не «когда понадобится».
